## 二、触发条件（满足任一即启动回滚）

| 等级 | 场景 |
|------|------|
| P0 | 导入即崩溃 / 已导入书籍全部不可读（数据损坏） |
| P0 | 隐私事故：正文、书名、Token 或 PII 外泄到任何外部端点 |
| P0 | 分页或章节识别导致主链路不可用（大面积无法阅读） |
| P1（评估） | 单一平台安装后白屏且无法自助恢复 |

> 非上述情形走 1.0.x 补丁，不整版回滚。

---

## 三、回滚步骤

### 1. 商店侧（Chrome Web Store / Edge Add-ons）

1. 进入开发者后台 → 该扩展 → 版本管理。
2. 上传 v0.8.1 包（`xyfy-txt-reader-v0.8.1.zip`），版本号已为 0.8.1，无需改动。
3. 提审并标注「紧急回滚」；Chrome 紧急回滚通常 1–24 小时，Edge 1–3 天。
4. 若商店审核过慢，先把商店详情页的「已知问题」公告改为指向 GitHub Release 的手动安装指引。

### 2. 仓库侧

```bash
# 1) 打回滚标签（不要删 v1.0.0，保留审计痕迹）
git tag -a v1.0.1-rollback-to-0.8.1 -m "1.0.0 回滚至 0.8.1：原因见 CHANGELOG"

# 2) 若需在 main 上还原代码（当前 1.0 与 0.8.1 代码一致，通常不需要）
git revert --no-commit 649ab34   # 1.0 冻结提交
git commit -m "revert: 1.0.0 冻结回滚（原因：<P0 描述>）"
```

### 3. 用户侧（数据安全优先）

- 回滚**不清除** IndexedDB 与 `chrome.storage`，用户书籍与进度不受影响。
- 若 P0 涉及数据损坏，先指导用户用「导出备份」导出 JSON，再回滚。

---

## 四、回滚后必做

1. 在 CHANGELOG 顶部记录回滚原因、影响范围、发现时间。
2. 在 GitHub Issues 建 P0 单并关联对应验收项。
3. 商店详情页发布公告，说明影响版本与已修复状态。
4. 复盘：补充到回归用例，避免同类问题再次进入发布。
