# Xyfy.TxtReader v0.7 测试用例与测试计划

> 对应 Epic [#29](https://github.com/xyfy/Xyfy.TxtReader/issues/29)，PRD 见 `docs/v0.7-prd.md`。
> 所有用例均有自动化实现，随 `npm test` 一起跑；下表「实现」列给出文件与断言组。

## 1. 测试策略

| 层次 | 做法 | 理由 |
|------|------|------|
| 逻辑层 | 纯函数单测（Node，无 DOM） | 六个功能的判定逻辑全部下沉到 `modules/`，可脱离浏览器验证 |
| 结构层 | 读 HTML 源码做结构断言 | 双端一致性、aria 语义、控件接线，正则足够且无需浏览器 |
| 集成层 | CDP 驱动真实浏览器走主流程 | 引导 → 场景 → 拖拽批量导入 → 统计 → 焦点陷阱，验证「接得上」 |
| 回归层 | TC-REG-01~06 | 防止 v0.4/v0.5/v0.6 的能力被新功能挤坏 |

TC-REG-06 是这版特意加的：模块写完但没接进 `reader.js` 或 HTML，是最典型的「假完成」，靠肉眼 review 很难发现。

## 4. 手工验证（无法自动化的部分）

| 项 | 做法 |
|----|------|
| 真实拖拽 | 在 Chrome 里把文件从资源管理器拖到阅读区，确认提示层出现、松手后导入 |
| 读屏 | Windows NVDA / macOS VoiceOver 打开浮层，确认 Tab 循环与关闭后焦点归位 |
| 触屏 | 手机 / 平板横竖屏切换，确认引导文案与推荐字号观感 |
| 观感 | 三套场景切换时有无闪烁、护眼配色是否真的「不刺眼」 |
